### 數學範圍讀取

- 分段總數與本機舊表不同時，若排程有原始日期，會在相同講義、冊別及主題中查回該日已知頁碼，不用分數推算頁數。例如移至 11/2 的「三角比（2/5）／（3/5）」，來源 10/13、10/14 分別對應 p.228–236、p.237–245。
- 沒有符合的原始日期或教材不符時，不借用其他科目、冊別或日期的頁碼。明確的 Calendar 頁碼與既有可完整對照的分段順序仍優先。
- 排程更新、合併子項與補做重建會保留手動修改（包含刻意清空）。同一項目的新排程無範圍時，保留已保存的相同教材頁碼與建議範圍；切換到不同教材則不套用舊書頁碼。
- 舊卡片已有講義及冊別但頁碼空白時，可補入相符的當日排程範圍，保留明確的手動欄位設定。

### 卡片顯示規則

- Tracker 與待辦卡片統一採「標題 > 範圍 >> 其他」層級：標題 22px／800，頁碼、Unit、回次及冊數 18px／650；欄位標籤、完成日期、進度勾選及說明降為 12–13px 灰字。可編輯的書名／講義選單以 20px 保持教材辨識；標題內保留的唯讀回次或單元也採範圍字級，不重複列出。桌面與手機使用同一套規則，保留科目淺色底及直接編輯範圍的操作。
- 書名只顯示一次：唯讀教材以標題為主；可編輯教材保留選單，移除標題重複書名。沿用教材識別處理完整名稱與簡稱，例如 Unlock 3。
- 頁碼、Unit、回次有輸入欄時，以輸入欄為主；唯讀回次若已在標題則不重複列欄。保留分段註記（例如 1/2）、來源日期、完成日期及計時控制。
- 課程與章節對照只補充尚未顯示的章節，不再重列頁碼範圍。若全部已出現在標題則隱藏空白對照區；修改範圍後會重新判斷並顯示新的章節。
- 文法排程保留重點，取消重複的建議頁碼。待辦使用同一套文字顯示規則，原始書名、排程、筆記及儲存資料不變。

## I. 使用方式

1. 開啟 Tracker，選擇日期後填寫今日狀態與各項進度。
2. 每張可計時卡片可點一下「手動／計時」切換；計時顯示分：秒，完成後換算為分鐘並四捨五入到小數點後一位。
3. 勾選項目、修改欄位或輸入文字時，內容會先保存到目前瀏覽器；重要的勾選、延期與刪除會立即保存，連續打字會短暫合併後再保存，減少手機卡頓。
4. 按「儲存紀錄」後，按鈕會分別顯示：
   - `已存本機 ✓`：本機已安全保存，但 Cloud 尚未完成。
   - `Cloud 已同步 ✓`：Supabase 已確認寫入完成。
   - `同步失敗`：本機仍保留；下次載入頁面或手動按儲存／同步時再試。
5. 登入 Cloud 後，可在不同裝置讀取同一帳號的紀錄；同時開啟多個分頁時，系統會先比較再上傳。登入前會先保存訪客草稿，登入後自動帶入已新增的項目、單字及教材設定；同日已有帳號紀錄時保留兩邊項目。重複登入不會重複匯入，原訪客資料保留；轉存失敗會列出日期並可重試。已轉存的訪客日期綁定首次登入的帳號，不會自動帶到其他帳號。
6. 整張自行新增卡片刪除前會再次確認；單字列、雜誌列與其他小項目刪除後可在 8 秒內按「復原」。
7. 「匯出與匯入」可先預覽 JSON，確認後才寫入，並可復原上次匯入。
8. 「作息時間」預設收合，展開後以同一組起床／就寢滑塊切換，共用小時與分鐘輸入；凌晨 00:00～05:59 的就寢會明確標示為隔日凌晨。
9. 右側工具欄的「待辦事項」集中顯示日期早於今天、仍未完成且未延期的正式排程；手機先點「工具」。可依全部／國文／英文／數學／自然／其他切換。每張待辦直接帶出原卡已填資料，可用手動／計時模式記錄時間、修改進度、選擇完成日期並完成，或按「跳過」停止顯示提醒。完成與跳過項目會移到獨立的「最近處理」清單，3 天內可跨重新整理復原。
   - 頁首灰字顯示目前的資料來源及實際讀取天數，旁邊的「重新讀取」為灰藍文字連結，直接重讀本機資料並保留目前科目／期間／項目篩選。移除原介紹文字及重複的「逾期未完成」說明列。
   - 待辦上方另有「全部／本月／本週」期間滑塊，預設全部，依原排程日期篩選，再與科目篩選交集。本月是目前曆月，本週是週一至週日，與週／月總結一致；仍只列今天以前的逾期未完成項目，因此月初或週一可能沒有本期待辦，舊項目可切回「全部」查看。
   - 期間旁顯示原排程日期範圍；目前期間與科目保存在網址，重新整理及瀏覽器返回／前進會還原。切換只影響清單顯示，不修改原始紀錄、停止背景計時或清除輸入草稿；跨午夜後一分鐘內更新目前週／月範圍。
   - 「查看項目」使用原生下拉選單，預設「全部項目」；依教材／項目的基本名稱分組，科目只顯示一次，不同日期、回次、Test、Unit、章節及頁碼範圍合為同一選項，例如「國文｜古今悅讀一百」「英文｜英文文法總複習」。此規則也適用未列入書目清單的教材；不同科目、不同教材及不同工作名稱仍分開。選單會依目前科目判別：選國文只列國文，選英文只列英文，選全部才列各科；切換科目或開啟不相容的舊網址時，不適用的項目選擇自動清除。各張原待辦的回次、單元、時間、進度與完成狀態保留並可獨立操作。再與期間篩選取交集；選項清單涵蓋該科所有逾期待辦，不因切到本週而找不到較舊項目。選擇保存在網址，重新整理及返回／前進可還原，舊版帶有回次或章節的網址自動對應到新的整組選項；已排除項目的舊網址不會讓該選項重新出現。完成或跳過最後一筆時保留所選項目並顯示空清單，選擇「全部項目」即可恢復目前科目的其他待辦。篩選不修改紀錄或停止計時，「最近處理」仍獨立顯示。
   - 「最近處理」沿用獨立的 72 小時復原清單，不受期間與科目篩選隱藏。
   - 在待辦按「完成」會回寫原排程日期的同一筆紀錄，原卡片與對應子卡同步勾選並顯示指定完成日期；在「最近處理」復原也會同步取消。其他範圍、時間、筆記及獨立進度不會被一併修改。
   - 返回原頁面、切換日期、重新整理或另一分頁完成時皆重新取得最新勾選；原頁正在輸入時等離開欄位後再合併更新，避免刷新掉草稿。
   - 原卡有「進度／批改／訂正」勾選欄時，待辦也會完整顯示；尚未寫入的勾選視為未勾選，不會漏欄。勾選與取消會直接保存至原紀錄，不會自動按下整張卡的「完成」，自然科的手動進度也會保留。

## II. 目前版本的重要功能及解說

### 教材目錄管理與單字升級

- 從標題列「教材進度圖」查看與管理教材，共用同一套卡片、表單及國文／英文／數學／自然科目切換，每本教材只列一次。預設只顯示進度；原「新增教材」位置改為「編輯」，點選後才顯示「新增教材」及各本教材的管理操作。按「完成」收起操作與表單，再次進入時保留尚未儲存的草稿，模式切換不會自動寫入紀錄。
- 進入編輯模式後，可在進度卡按「編輯」或按「新增教材」，設定書名、科目、分類、頁碼／Unit／回次模板、總數及章節對照。科目提供國文、英文、數學、自然；選自然後再選生物、物理、化學、地科，既有教材編輯時會還原原分科。儲存後原頁立即更新，不必切換管理頁。大單元相同的小主題可分列不同範圍，範圍不得重疊，結束值必須大於或等於起始值。未知末頁先補上總數，不猜填。
- 既有教材卡片仍可編輯範圍、查看大小章節對照及保存進度，教材進度圖僅按大單元分界。「刪除目錄」只在點選既有教材的「編輯」後顯示，位於表單下方，新增教材時不顯示；刪除仍先確認，取消確認會保留草稿。刪除目錄只停用新項目選用，不刪除既有紀錄；可恢復教材或將內建教材還原預設設定。改名以穩定教材 ID 保留已填進度。
- 教材設定屬於目前訪客／帳號，使用既有紀錄 JSON 保存；先存本機，返回 Tracker 後排入雲端同步。停用的教材可勾選「顯示已停用教材」後恢復；切換科目、搜尋及重新讀取會保留開啟中的編輯草稿。同一教材跨頁籤同時修改時，後存者會收到清楚提示並保留草稿。舊 material.catalog.html 連結自動導向教材進度圖，保留查詢及科目位置。
- 單字在不同日期出現兩次以上時顯示「🔥 記錄 N 次」，同一天的重複輸入與合併來源只計一天，不寫死日期範圍或單字數。英文文字仍連至 Oxford。
- 單字旁的喇叭採灰色圖示、透明背景，按下才發音，可選美式／英式；同一按鈕再次按下停止，切換單字先停止前一筆。使用裝置的瀏覽器語音，是否可離線取決於裝置已安裝的語音；不新增發音音檔庫或後端 API，不支援或失敗時顯示提示，單字編輯與中文顯示切換仍可使用。

### 1. 今日項目與本週項目

- 今日／本週使用滑塊切換。
- 同科目相鄰排列，讀書卡片使用各科主題的淺色底、科目色左邊線與標題，與灰藍色頁面背景區分；移除內層欄位小卡及自然整合子卡的重複外框。今日資訊、連線設定及統計面板保留原用途與操作。
- 自然整合四科的科名只顯示於勾選旁標題，不再重複列唯讀「科目」欄。桌面重新分配講義與頁碼欄位，手機沿用講義單列及起訖頁同列；一般自然卡片的可編輯科目選單保留。
- 其他卡片若標題已顯示同一書名、科目或講義，會省略重複的唯讀欄位並重新分配欄寬；包含 Azar、文法講義、國文回次、Unit 與教材目錄模板。可編輯的選單、頁碼、回次及 Unit 輸入保留，原始紀錄不刪除。
- 頁碼／Unit／回次的範圍輸入持續顯示，可直接編輯；「課程與章節對照」預設展開，也可自行收起，只列教材的對應單元、主題與章節，不重複列出 Google Calendar 當日主題或數學建議進度／建議頁碼。修改範圍時即更新對照，原始 Calendar 資料仍保存。完成日期、計時與進度／批改／訂正維持獨立操作，手機頁碼以起訖兩欄同列排列。
- Tracker 與待辦卡片不顯示自動產生的「Google Calendar API：…」原始來源內容，Calendar 補做卡也不顯示「今日補做｜Google Calendar」。若原說明在來源文字之前有學習指示，仍保留該段；原始排程描述繼續保存供解析、合併與同步。
- 選擇「外出」不會取消或隱藏原有排程；項目仍可照常勾選、填寫時間與查看當日進度。
- 「互動題」改為每日選做；數 A、英文、生物及單字／片語互動子項目皆不列入原訂今日、今日總項目、週五／本週結算及週／月完成率的分子與分母，完成或未完成都不影響必做完成率。新排程、Calendar 與舊版仍標為必做的互動題皆使用相同規則，不需逐日開啟舊卡片才生效。仍可照常新增、填寫、計時與勾選，實際完成日期、已完成學習時間及週／月完成清單保留；週一原有單字驗收列仍自動顯示，但同樣為選做。
- 先依範圍類型選模板：有 Unit／回次（第 N 回／Round／Test）且附分段分數註記（如「（1/2）」、「（2/2）」或「進度：1/2」）時，用起始頁／結束頁；沒有分段註記則繼續用既有 Unit／回次模板，不因教材未列入書名清單而失效。此規則適用所有科目、原卡片、Calendar 新排程及待辦，不只 Unlock 3。一般無註記日期（如 10/25）、標明原日期及不合法分數不當成分段。
- 分段項目優先保留已填頁碼或讀取 Calendar 明確頁碼；未提供則留空供填寫，不把 Unit／回次數字當頁碼，也不依 1/2 自行估算半本單元。既有 Unit／回次欄位、時間、勾選與完成日期保留在資料中。教材進度圖仍以大單元分界，但分段只按實際填入頁碼累計，不冒算整個 Unit／回次；沒有頁碼地圖的回次教材不推算頁數與回次的換算。Calendar 日後移除分段註記並重新同步時可恢復 Unit／回次模板，已填頁碼不刪除。
- Azar 文法書沿用自然教材的印刷頁碼讀取方式，但不需要「講義版本」；同章相鄰的 Calendar 頁碼合為一張卡片，顯示書名、可編輯的起始／結束頁、當日主題及頁碼對應章節。舊分項的勾選、分鐘與實際頁碼會搬入合併卡。
- 排程項目的相同連續範圍可合併；中斷範圍或不同回次保留為同一大卡中的獨立子項目。「自行新增項目」一律各自獨立，不合併頁碼、回次、Unit 或相同模板，也不併入排程卡；原先已合併且仍保存原始來源的手動卡，重新載入時會還原成各張卡。
- Unit／回次判斷共用於所有科目、既有卡片、Calendar 新排程及待辦；沒有書名地圖的教材也適用。保留 ACE、英聽、寫作、主題百匯、Essential Grammar in Use 等已具備正確模板的專用控制。Unlock 3 與 Essential 的 Unit 上限仍為 8／115；未知教材不臆測上限。Unit、回次及頁碼分開保存，手動修改不會被排程刷新覆蓋；沒有實際頁碼對照的 Unit／回次不冒充頁碼進度。

### 2. 延期與完成率

- 「英文訂正與搭配詞整理」及「數學講義題目：理解檢查＋錯題標記＋訂正」不列入待辦事項；原日期卡片與所有已填資料仍保留，其他數學講義進度照常列入。
- 所有互動題不列入待辦與待辦頁的「最近處理」：包含每日互動題整組、數學觀念題、英文英聽及學測練習、生物、單字／片語，以及舊版／Calendar 互動題。混合合併卡只排除互動題來源，其餘教材待辦保留。不會刪除原卡、標記跳過／完成或更改計時；互動題統一使用每日選做規則，完成率排除互動題，已完成學習時間與週／月完成清單保留。
- 「英文歷屆／模考：限時作答」「英文歷屆／模考：批改與訂正」「英文：混合題與作文練習」「學測英文訓練：英文雜誌」固定項目及《大考英聽A攻略》所有回次不列入待辦、查看項目選單與最近處理；依標題、舊版識別碼、Calendar 模板及書名欄位辨識。其他科目模考、其他英聽教材及雜誌教材仍可列待辦。原卡片的分鐘、分數、頁碼、回次、批改訂正與完成紀錄保留，已完成項目照常列入週／月總結。
- 延期必須選擇目標日並按「確認延期」後才生效。
- 每個目標日預設最多 3 項，超過時會再次詢問。
- 確認延期後，原訂今日項目與今日總項目的分母都會減少一項，不會把延期誤算成完成。
- 子卡片可分別延期、完成、手動填入時間或計時。
- 英文混合題與歷屆／模考限時作答排在同一天時，必須在今日項目中自行選擇一項；未選擇前兩項都不計入，選擇後只顯示並統計所選項目。可隨時改選，另一項已填內容會保留；若週五選模考，週六會安排批改與訂正。
- 「週五結算完成率」固定以週五為截止日；週六、週日才勾選的平日項目不會回填並改寫週五快照，但仍會正常納入截至週日的本週結算。
- 「待辦事項」只整理過期未完成排程，不會另建一張重複卡片。每筆會顯示原日期、科目、項目類型及原卡已填的教材、頁碼、單元、主題、批改／訂正等內容；可切換手動／計時、修改既有進度勾選，學習分鐘與指定完成日期皆直接回寫原紀錄。完成與跳過按鈕使用精簡尺寸；處理後統一移至獨立「最近處理」清單，72 小時內可復原，逾期後自動從復原清單移除。標記完成後沿用實際完成日期的統計規則；按「跳過」只移除待辦提醒，原項目仍維持未完成。
- 項目只要不是在原日期當天勾選，不論提早或延後，都會保存實際完成日，並將該項時間計入實際完成日；同日完成仍計在原日期。勾選後一律在項目標題及標題備註下方顯示可修改的「完成日期」，修改時同步重新歸屬學習時間與延期原日期；取消勾選會清除日期紀錄。即使作息時間只暫填一半，勾選與完成日期仍會獨立保存，且不會誤寫或清除尚未完成的作息草稿。
- 延期項目在延期日完成時，延期卡會保存實際完成日，並同步勾選原日期的來源項目；取消延期完成勾選時也會同步還原來源項目。

### 3. Google Calendar 唯讀整合

- 數學分段頁碼依講義版本、冊別及單元辨識，使用既有排程表中的實際分段；不再要求行事曆標題與舊表完全相同。例如「4A｜條件機率與貝氏定理」的 1/4、2/4 對應 p.151–162、p.163–174，即使從 10/7、10/8 移到 10/29 仍使用原分段。支援括號／全形分數與寫在標題的分段；明確頁碼永遠優先。其他講義不套用教學講義頁碼，分母與對照表不符或單元不明確時保留空白供手動填寫。跨冊標題保留原分段順序，並核對所選分段的實際冊別。
- 多筆數學行程先保留各自來源紀錄，再合併顯示連續頁碼，避免模板提前合併而漏掉第二筆分鐘；各筆完成、分段範圍與手動覆寫皆保留，重新同步不覆蓋使用者主動修改的頁碼。
- 使用 `calendar.events.readonly` 讀取行程，不會修改或刪除 Google Calendar 原始資料。
- 已知模板依原有欄位建立；其他行程只有在能辨識國文、英文、數學、自然細科或社會科目時才加入 Tracker，完全無法判斷科目的行程會忽略。`本週項目｜名稱` 加入本週項目，Calendar 補做仍加入今日項目。
- 同步包含新增、修改與刪除，避免已刪除的 Calendar 行程留在 Tracker。
- 連線、讀取、同步或逾時出錯時，沿用同帳號最後成功排程，並優先保留該帳號已保存的項目、勾選、頁碼、時數與筆記；沒有快照也不以內建排程重寫舊紀錄。快照按帳號保存於此瀏覽器、支援重整，只有完整成功的回應（含真正空排程）才更新；遲到結果不套用，成功手動解除連線會清除此帳號快照。
- GitHub Actions 可每小時呼叫後端同步，網站不必保持開啟。

### 4. Local-first 與 Supabase 雲端同步

- 所有輸入先保存本機；只在載入 Tracker／日期、手動儲存或同步時上傳。
- Cloud 狀態會顯示「同步中」、「待同步 X 天」、「已同步」或「同步失敗」。
- 移除每 5 秒待同步掃描、每 10 分鐘自動儲存及切回視窗／恢復網路的自動重試；失敗後停止並提示手動重試。
- 雲端資料抵達時若使用者正在輸入，不會強制重畫；失焦後會安全合併，亦可按「立即套用」。
- 同一日期在多分頁／多裝置修改時，以穩定項目 ID 與共同基準交叉比對；不同欄位可合併，同一欄位衝突則保留兩邊並提示處理。

## VIII. 注意事項

- 不要把 `GOOGLE_CLIENT_SECRET`、`GOOGLE_STATE_SECRET`、`CALENDAR_CRON_SECRET`、Supabase service role key 或資料庫密碼放進前端或 Git。
- Supabase publishable key 與 Google OAuth Client ID 是前端公開識別碼，但應由既定設定流程管理。
- 瀏覽器若禁止 persistent storage，Tracker 會顯示警告；此時不要把「已暫存」理解成關頁後仍一定存在。
- Google Calendar 只讀 scope 不代表同步後的 Tracker 副本不含個人資料；資料刪除與隱私權政策仍需和實際行為一致。
- 建置若只出現 JavaScript chunk size 警告，不會阻止發布；後續可繼續拆分 `legacy-app.ts` 以降低載入與修改風險。

### v171.6.150：尚未記錄的排程以雲端為準

Actions／Calendar 的排程差異不等於實際紀錄衝突。當日只有自動排程、版次或同步旗標時，採用已確認的雲端紀錄；完整 Calendar 更新也能解除舊的純排程衝突，不要求人工選擇版本。有勾選、時間、單字、作息、筆記、手動範圍、手動新增項目或已清除的既有輸入時，保留原本合併與欄位衝突保護。資料損壞、跨帳號、過期版次、同步中與失敗回應仍不覆蓋資料。沿用 v149 的排程更新與實際紀錄保存；本版只需更新前端，無新 migration、Secrets 或套件。

### v171.6.151：待辦手機排版測試等待動畫穩定

`overdue task page filters subjects and persists skip without marking completion` 在展開後立刻切換手機尺寸，先前只等待編輯內容出現，未等待展開動畫清理。現在使用共用 `expandTodoCard`，確認動畫結束及手機寬度生效後，再以可重試的相同防重疊條件讀取最終位置，保留原本日期、按鈕及卡片寬度的嚴格檢查。新增暫停開啟動畫的瀏覽器驗證，確認內容已存在時動畫仍可能進行。本版更新 CI 檢查與版本文件，保留既有展開動畫及 UI。

### v171.6.152：只在載入或手動操作時同步

純 Calendar 排程更新僅作本機快取，不算使用者新增讀書紀錄，也不列入待同步天數。既有誤標的純排程待同步會在完整比對後清除；真正輸入、勾選或清空紀錄仍保留原雲端共同基準並正常待同步。
登入尚未確認時切換帳號快取中的日期，也不會以內建排程取代已保存項目。

Actions 每小時在伺服器更新 Calendar 的排程保留。Tracker 載入時先讀取 Cloud 與 Calendar，完成比對後只排入一輪待同步紀錄；手動儲存、重試、重新讀取或 Calendar 同步也可啟動一輪。輸入、失焦、其他分頁通知、切回視窗及恢復連線只更新本機或狀態，不自行發出資料同步。待辦與總結只在載入（含返回快取）或手動重新讀取時取得 Actions 排程，不再每分鐘輪詢。失敗後等待手動重試或下次載入，已有暫停選擇保留。同步途中再修改內容時，新內容留在本機待下次同步，不連鎖上傳；登入權杖更新與計時顯示保持正常。
